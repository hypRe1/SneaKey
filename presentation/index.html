How SneaKey works

01

Find the clicks

Spot sudden jumps in loudness.

02

Keep real presses GBDT

Throw out key releases and background noise.

03

Name the key SVM

Match each press’s sound fingerprint to a key, with a score for every key.

04

Filter to real words LM

Keep only the likely letters, then pick the most English-looking text.

One sentence per step: 1. “First we find the clicks: moments where the sound suddenly jumps compared with the room’s background.” 2. “Not every click is a key press. Keys click on release too, so a gradient-boosted tree model checks 13 traits of each click and keeps the real presses.” 3. “For each press we take a 32 ms fingerprint of its pitches, and an SVM, which learned where each key’s fingerprints fall, scores every key.” Point at the figure: “Here it’s squashed to 2D. T’s clicks on one side, H’s on the other; a new click is named by which side it lands on.” 4. “That gives us a probability for each key, so only a few letters are possible per click. A language model then picks the combination that looks most like English.” The figure is an illustration, not real data.

“Random guessing gets 2%, and always guessing Space gets 16%. From the recording alone we name about half of all keys. When we find the click correctly, it’s 56%, and the right key is in our top 5 guesses 82% of the time.” Why the gap between 50% and 56%: some presses are missed or mixed up with key releases and noise.
